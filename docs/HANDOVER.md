# 인수인계 — 지금 상태

이어받는 사람(사람이든 에이전트든)이 **이 문서 하나만 읽고 시작**할 수 있게 적는다.
자세한 규칙은 `docs/RULES.md`, 작업 규칙은 `CLAUDE.md`.

---

## 이 앱이 무엇인가

PL교회 제자훈련(DG) 조 배치·출석 앱. `dgfinder.plch.kr`.

```
원본 = 구글 시트          DB(Supabase) = 버려도 되는 사본
  ├ 출석부(DB) 탭          앱 조회는 DB 를 직접 읽는다 (빠르다)
  ├ 김밥 탭                쓰기는 언제나 시트로 모은다 (GAS doPost)
  ├ 과제제출 탭 (폼 응답)
  └ DG링크 탭
```

| 화면 | 파일 | 누가 |
|---|---|---|
| 조회 | `index.html` · `script.js` | 조원·조장 (이름+전화 뒷 4자리) |
| 관리자 | `admin.html` · `admin.js` | 관리자 (Supabase 로그인 — `scripts/admin-auth.js` · 함정 6-11) |
| 데이터 계층 | `scripts/members-data.js` | 화면은 여기만 통해 데이터를 만진다 |
| 출석표 렌더러 | `scripts/matrix-renderer.js` | 두 화면이 함께 쓴다 — 고치면 **둘 다** 바뀐다 |
| 시트↔DB 동기화 | `scripts/sync-sheet-to-db.mjs` + `.github/workflows/sync-db.yml` | 2시간마다 |
| GAS | `scripts/gas/doGet.js` (사본) | 시트 읽기·쓰기, 10분 트리거 |

## ⚠️ 여기서 사람이 계속 넘어진 곳 셋

### 1. 출석표 칸 값은 `m.attendanceByDate` 에서만 읽는다

`renderTeamMatrixHTML()` 의 기본값이다. 그런데 **그 객체를 전 회차로 채우는 길은 없다.**
`loadAttendanceForSession()` 이 넣은 **읽은 회차**만 들어 있다. (예전에는
`refreshAttendance()` — GAS 로 시트 전체를 읽는 왕복 — 가 조회 화면에서만 채웠다.
v131 에서 없앴다 · 함정 6-9.)

→ 이 렌더러를 쓸 때는 **`getStatus` 를 반드시 넘긴다.** 두 화면이 지금 그렇게 한다.

```js
renderTeamMatrixHTML(name, members, extras, {
  getStatus: (m, d) => abHistory.get(m._uuid)?.get(d) ?? '',   // 관리자: getAttendanceHistory()
});                                                             // 조회:   getTeamAttendance(members)
```

안 넘기면 나머지 열이 전부 `·` 로 나오는데 **오류가 안 난다.** 게다가 같은 브라우저로
조회 화면을 먼저 열었으면 localStorage 캐시 때문에 맞아 보인다 —
**확인은 반드시 시크릿 창에서.** (v108 에서 실제로 이 사고가 났다.)

### 2. 버전은 `npm run bump` 로만 올린다

`?v=` 를 손으로/다른 도구로 붙이면 **node 전용 파일(`tests/*.mjs`,
`scripts/*.mjs`)에도 붙는다.** 브라우저가 안 받는 파일이라 쓸모가 없고, 올릴 때마다
바뀐 파일로 잡히고, 검증이 깨진다. `bump-version.mjs` 가 그 둘을 일부러 뺀다.

```
npm run bump         # +1
npm run bump:check   # 어긋난 곳만 보고 (고치지 않음)
```

### 3. GAS 재배포는 '배포 관리 → ✏️ → 새 버전'

**'새 배포' 를 누르면 URL 이 바뀌어** GitHub Secrets 의 옛 URL 이 404 가 된다.
자세한 것은 `scripts/gas/README.md`.

### 4. GAS 프로젝트가 **둘**이다

| | 어디 | 무엇 |
|---|---|---|
| `scripts/gas/doGet.js` | dev 계정의 **독립 프로젝트** (`SHEET_ID` 로 시트를 연다) | 웹앱 `doGet`(동기화가 부른다 · **읽기 열쇠**) · `doPost`(앱 저장). 배포 대상 |
| `scripts/gas/sheet-bound/` | **출석부(DB) 시트에 직접 붙어 있다** | 메뉴 · `onEdit` · `onFormSubmit`. **배포 없음** |

헷갈리면 엉뚱한 쪽을 고치고 아무 일도 안 일어난다.
**시트 쪽이 출석 칸에 `'과제'` 를 쓴다** — `scripts/gas/sheet-bound/README.md` 와
`docs/RULES.md`.

- **버전(v30 · v31 · v32 …)은 전부 dev 쪽 이야기다.** v32 도 dev 계정 독립 프로젝트에
  붙여넣고 재배포했다 (2026-11-07). 출석부에 붙은 GAS 에는 버전이 없다.
- 그래서 `doGet.js` 를 고치면 **머리말의 ⚠️ 상자와 버전 기록 첫 줄**
  (`v33 — dev 계정 독립 프로젝트`)에 붙여넣을 곳을 적는다 (CLAUDE.md 4).
- `doGet.js` 의 **`DGfinder` 메뉴(`DG_addMenu`)는 시트에 안 붙는다** — 독립 프로젝트의
  함수는 시트에 붙은 `onOpen` 이 부를 수 없다. '과제 아이디 점검'(`DG_checkHomeworkIds`) ·
  '10분 트리거 등록'(`DG_installTrigger`) · '지금 DB 에 맞추기'(`DG_pushToDb`)는
  **dev 프로젝트 편집기에서 함수를 골라 ▶ 실행**한다. 10분 트리거도 dev 프로젝트의 ⏰ 에 있다.

### 5. 자동 새로고침은 `dg_sync_log` 하나만 본다

`dg_members.updated_at` 을 보면 안 된다. 동기화는 `dg_members` 를 **맨 먼저** 쓰고
`dg_attendance` 를 **맨 마지막**에 쓴다. 예전에는 첫 표가 끝나는 순간 새로고침이
돌았고(출석·과제가 아직 안 들어온 시점), 폴링이 그 시각을 이미 본 것으로 올려 버려
**두 번째 새로고침이 영영 오지 않았다.**

→ `sync-sheet-to-db.mjs` 가 **맨 마지막에** `dg_sync_log` 에 한 줄을 넣는다.
화면은 그 줄만 본다. 표가 없으면 `dg_attendance.updated_at` 으로 물러난다.

### 6. `dg_homework` 는 `kind` 까지 봐야 한다

`select=lecture` 만 하면 **그 강의에 제출이 하나라도 있으면** 인정으로 친다.
과제만 낸 사람이 '과제+소감문 제출' 로 읽힌다 — 실제로 그 사고가 났다.
인정 판정은 `isFullHomework()` 하나만 쓴다. `docs/RULES.md`.

### 6-1. 아이디만 있는 응답은 제출이 아니다

시트를 읽는 GAS(`DG_readHomework`)가 거르는 것은 **아이디뿐**이다. 폼에서 문항을
안 고르고 낸 응답이 `lecture=''` · `kind=''` 로 그대로 들어오고, 기본키가
`(cohort_id, member_id, lecture, kind)` 라 **사람마다 한 행**이 자리 잡는다.
화면에 `(미기재)` 로 남아 '총 N건 제출' 까지 부풀렸다.

**기준은 `lecture`·`kind`·`content` 가 셋 다 비었을 때다.** 하나라도 있으면 남긴다 —
'몇 강' 을 안 적고 낸 **진짜 제출**은 `(미기재)` 로 보여주는 것이 맞다. 제출 시각은
기준이 아니다(타임스탬프만 있는 것은 제출이 아니다). 거르는 자리는 둘 —
`getMyHomework()`(화면 즉시)와 동기화(넣지도 지우기도).

### 6-2. 안 낸 과제는 **빈칸을 묻지 않는다**

`homeworkRule(status)` 한 곳이 정한다. `X`→`'과제+소감문'`, `O`·**`돌봄`**→예습과제,
**`과제`·빈칸·`−`·`◎`→아무것도 안 묻는다.** (`과제` 는 시트가 이미 확인했다 — 6-8)

돌봄은 그 자리에 있었으므로 예습과제는 묻는다. 그래도 `isPresent` 에는 안 넣는다
(`isCare` 로 따로 본다) — 넣으면 조 요약·결석 현황·하차 검토가 한꺼번에 바뀐다.

빈칸을 안 묻는 것이 핵심이다 — 합류 전·**하차 기간**·아직 저장 전을 앱은 구별할
수 없다. DG 는 재합류가 있어서(7월 합류 → 8월 하차 → 10월 재합류) '첫 기록부터
센다' 는 옛 창으로는 8~9월치가 딸려 나왔다. **합류 시점 열은 만들지 않았다** —
이유는 아래 '남은 일'.

### 6-3. 빈칸→X 는 되돌렸다 — 대신 지난 회차를 묻는다

저장하면 손대지 않은 빈칸도 X 로 나간다(작업 #31). **기록이 하나도 없는 사람도
빼지 않는다** — 명단에 있으면 결석자 명단에 떠야 교역자가 조치할 수 있다.

막는 것은 둘뿐이다.

- **관리자에서 조를 안 골랐으면(전체)** 빈칸을 안 보낸다. 범위가 기수 전원이라
  한 명을 고치려다 전원에게 X 를 쓴 사고가 실제로 있었다
- **지난 회차**에 빈칸→X 를 쓰려 하면 한 번 묻는다 (`isPastSession`). 화면의
  명단은 늘 오늘의 것이라 그때 없던 사람에게까지 X 가 간다. 조장 화면에도
  회차 선택이 있다 — 관리자만의 문제가 아니다

### 6-4. 개인 화면도 '다가오는 회차' 를 본다

`getMyAttendance` 는 오래 `date <= today` 로 잘랐다. 그래서 **조회 화면 그리드와
관리자 개인 상세**(둘 다 이 함수를 쓴다)가 다가오는 회차를 아예 몰랐다. 조별
매트릭스만 멀쩡했던 것은 `buildSessionColumns()` 가 `getSessions({throughNext:true})`
로 따로 만들었기 때문이다. 지금은 **데이터 계층이 그 규칙을 쓴다.**

⚠️ **세는 곳은 `!r.upcoming` 으로 거른다.** 총 회차·출석·결석·🍙·📝, 그리고 접기 셈
(`folded`·`md-att-hidden`)까지. 안 그러면 '총 22회차' 가 23이 되고 최근 10회차가
9회차만 펴진다.

김밥은 그 위에 하나 더 있다. 결과 카드의 `김밥: O`(`dg_members.lunch`)는 시트에서
**다가오는 회차 한 열**을 읽은 값이고 요약은 `dg_lunch` 다. 요약이
`getUpcomingLunches()` 로 다가오는 신청을 **전부** 읽어 함께 보여준다 — 한 달치를
한꺼번에 신청하는 일이 흔하다.

⚠️ **신청 판정은 `DG_isLunchApplied()` 하나만 쓴다.** v25 가 회차별만 고치고
`kimbapMap` 을 빠뜨려서, `X` 라고 적은 사람이 김밥 대상자로 세어졌다 (조 요약의
🍙 N · 조원 명단 🍙 도 그 값이다). v30 에서 맞췄다 — **재배포해야 반영된다.**

### 6-4b. 명단 차례 — 역할을 위로, 나머지는 시트 순서. **서열은 코드에 없다**

`compareLeadFirst()`(`members-data.js`) 하나가 정한다. 역할이 있으면(비었거나
`조원` 이 아니면) 위로, 그 안팎은 `compareMemberOrder`(시트 줄 번호).
매트릭스와 조회 화면 조원 명단이 쓴다. 출력물·관리자 명단은 `compareMemberOrder`
그대로 — 역할을 올리지 않고 시트를 비춘다.

예전에는 `{ 관리자:1, 조장:2, 서브튜터:3, 조원:4 }` 표를 **두 파일에 복사해 두고**
`|| 4` 로 물러났다. 표에 없는 **`부조장` 이 조원 등급**이 돼 명단 가운데 끼었다.
오류가 안 나서 아무도 몰랐다. 조장·부조장 중 누가 위인지는 시트가 이미 그 차례로
적어 두었으니 코드가 서열을 따로 갖지 않는다 — **시트에 역할이 늘어도 저절로 위로 간다.**

⚠️ 조원끼리 차례도 이름순 → 시트순으로 바뀌었다. 종이 출석부와 차례가 다르면
옆줄에 체크하게 된다(`compareMemberOrder` 주석). 조회 화면 조원 명단이 그동안 빠져
있었다.

### 6-5. 이름 칸에는 전화 뒷 4자리가 함께 있다

이름+뒷번호를 적는 자리가 넷이다 — 조원 명단 · 종이 출석부 · 관리자 개인 상세 ·
**전체 출석표**(매트릭스). 동명이인을 이름만으로는 구별할 수 없어서다.

꼴의 단일 출처는 종이 출석부다: 겉 `span` 안에 번호 `span` 을 넣는다
(`.pr-nm > .pr-phone`, 매트릭스는 `.mx-name > .mx-phone`).

⚠️ **`.mx-name` 의 `textContent` 는 이제 `'조원021001'` 이다.** 이름으로 줄을 찾는
코드·검증은 `.mx-phone` 을 떼고 견뎌야 한다. 안 그러면 조용히 아무 줄도 못 찾는다.

⚠️ 이름 열(`.mx-name-cell`)은 가로 스크롤 중에도 **붙어 있는 칸**이다. 넓어지면
그만큼 회차가 안 보인다 — `verify-matrix` 가 폰 폭에서 그 폭을 재고 있다.

### 6-6. 예약 동기화는 cron 대로 안 오고, 끝 표시는 조용히 빠질 수 있다

**둘 다 '고장인데 멀쩡해 보이는' 갈래다.**

- **예약 실행이 흘러간다.** `sync-db.yml` 은 2시간마다(하루 12번)로 적혀 있지만
  실측은 **하루 네 번쯤**이다 (2026-08-08~09-28, 218회/51일 · 간격 3~8시간).
  GitHub 쪽 일이라 못 고친다. Supabase 7일 pause 방지에는 넉넉하다.
  화면 문구가 '두세 시간마다' 인 까닭이다 — '2시간마다' 라고 적으면 그 시각에
  안 온 것을 고장으로 읽는다.

- **`dg_sync_log` 는 시퀀스를 쓰는 유일한 표다.** `id bigserial` 이 만드는
  `dg_sync_log_id_seq` 에 권한이 없으면 insert 가 `permission denied for sequence`
  로 막힌다. `grant all on <table>` 은 시퀀스를 안 덮는다.
  동기화 스크립트는 **경고만 남기고 계속 가고**, 화면은 `fetchSyncMark()` 가
  `dg_attendance.updated_at` 이라는 옛 신호로 **조용히 물러난다**.
  → 실제로 51일 동안 이 표가 빈 채로 돌았고 아무도 몰랐다.
  그래서 관리자 화면에 **마지막 동기화 줄**(`#syncLast`)을 뒀다 — 기록이 없으면
  거기서 빨갛게 말한다.

### 6-7. 김밥 탭을 못 읽으면 김밥이 **얼어붙는다** — 그래서 경고가 생명이다

GAS 가 김밥 탭을 못 읽으면 동기화는 **넣지도 지우지도 않는다.** 그게 맞다 — 못 읽었다고
지우면 전원의 김밥이 사라진다. 대신 DB 의 김밥이 마지막으로 읽힌 때 그대로 **굳는다.**

2026-10 에 실제로 났다. 김밥 탭 위에 줄이 하나 더 붙어 `id` 머리글이 **6행**으로 밀렸고,
머리글은 위 5줄까지만 찾았다. **10/8 ~ 10/17 열흘 동안** 새 신청이 안 들어오고 취소가 안
빠졌다. 로그는 엉뚱한 안내(`v21 로 재배포 필요`) 한 줄 뒤에 `✅ 동기화 완료` 로 끝났고,
관리자 화면은 `김밥 0` 을 그냥 숫자로 보여줬다 — **아무도 몰랐다.**

v31 이후:

- 머리글을 **위 10줄**까지 찾는다 (`DG_HEADER_SCAN_ROWS`). 칸 값이 정확히 `id` 여야 하므로
  데이터 줄과 헷갈리지 않는다
- 못 읽으면 GAS 가 **이유**를 준다 — `lunchReason`: `no-sheet` · `no-header` · `no-dates`
- 동기화가 그 이유를 적고 **`✅ 동기화 완료` 바로 위에 한 번 더** 말한다.
  `dg_sync_log.lunch` 를 `0` 이 아니라 **`null`** 로 남긴다 — '신청 0건' 과 '못 읽음' 을 가른다
- 관리자 화면 마지막 동기화 줄이 `null` 을 보면 **빨갛게** 알린다
- **같은 탭은 한 함수가 읽는다.** 결과 카드의 김밥(`kimbapMap`)이 따로 날짜를 해석하던 30줄을
  걷어내고 `DG_readLunchByDate` 결과에서 고른다. 예전에는 한쪽만 고장 나 카드·조 요약은
  맞아 보이는데 목록·출석부만 굳을 수 있었다. 이제 같이 고장 나고 같이 낫는다

⚠️ 김밥 탭의 날짜 머리글은 `10/18` · `10/18(토)` · `2026. 10. 18` · 날짜 값을 읽는다.
**출석부 탭은 예전처럼 `10/18` 과 날짜 값만** 읽는다 — 거기서 무시되던 머리글이 회차로
잡히면 회차 목록이 바뀌기 때문이다.

### 6-8. 노란 칸(`과제`)의 📝 는 기록이 아니라 **시트 표기**를 따른다

시트의 `'과제'` 는 10분 트리거(`DG_pushToDb`)로 DB 에 오지만, 제출 기록(`dg_homework`)은
**GitHub 동기화로만** 온다 — 실측 3~8시간 뒤(6-6). 그 사이 칸은 노란데 기록이 없다.

예전에는 조회 화면이 노란 칸에 📝 를 일부러 안 붙였고, 전체 출석표는 기록이 있을 때만
붙였다. 그래서 '8강 과제 처리됐는데 아이콘이 없다' 는 제보가 났다(v130). 게다가
`homeworkRule('과제')` 가 `'any'` 라 같은 사람의 '안 낸 과제' 목록에 그 강의가 떴다.

지금은 노란 칸에 **언제나** 노란 📝(`.hw-badge`) — 조회 화면·전체 출석표·관리자 상세가
같다. 툴팁이 기록 유무를 가른다. `homeworkRule('과제')` 는 `'none'` 이다.
**기록이 다음 동기화 뒤에도 안 들어오면** 폼 아이디가 명단과 다른 것이다 —
'과제 아이디 점검' — dev 프로젝트 편집기에서 `DG_checkHomeworkIds` 실행 (함정 4).

### 6-9. 조장 화면이 GAS 로 시트 전체를 읽고 있었다 — 11~102초 (v131 에서 DB 로)

조장이 조회하면 화면은 DB 를 안 쓰고 `refreshAttendance()` 로 **GAS `doGet` 을 불러 시트
전체**(탭 넷 · 261명 × 39회차)를 받았다. 동기화 로그 실측 한 번에 **11~102초.** 정작 쓰는
것은 한 조의 한 회차뿐이었다. 그동안 세 가지가 한꺼번에 났다 (모바일 제보, 2026-11):

- **'회차를 알 수 없어 저장하지 못했습니다'** — 회차(`state.session`)가 그 응답에 딸려
  와서 기다리는 동안 비어 있었다. 선택칸에 `selected` 가 없어 브라우저는 첫 항목(11/01)을
  보여줬다 — **보이는 회차 ≠ 앱이 쥔 회차**
- **요약 0 · 0 · 그 외 7** — 기다리는 동안 DB 의 '오늘'(수업 없는 월요일)을 셌다
- **체크가 사라짐** — 로딩 표시가 없어 빈 명단에 체크했고, 응답이 오면 다시 그리면서 날아갔다

지금은 `ensureSession()` 이 캐시된 회차 목록으로 **바로** 가장 최근 지난 회차를 정하고
(GAS `currentSession` 과 같은 규칙), `loadAttendanceForSession(session, { members })` 로
**그 조 · 그 회차만** DB 에서 읽는다. 받는 동안은 체크·저장을 막고 '불러오는 중' 이라고
말한다. 못 받으면 다시 시도 — 저장은 계속 막는다(빈 명단을 저장하면 전원이 X).
같은 조 · 같은 회차를 다시 그릴 때는 저장 안 한 체크를 옮겨 심는다(`pendingChecks`).

⚠️ **DB 가 뒤처지는 폭은 정해져 있다.** 앱에서 저장한 것은 GAS 가 그 자리에서 DB 에 민다
(`dbPushed`). **시트를 손으로 고친 것은 10분 트리거 `DG_pushToDb`** 가 옮긴다 — 이 트리거가
죽어 있으면 손으로 고친 값이 다음 동기화(3~8시간)까지 조장 화면에 안 나온다.
개발 계정 Apps Script ⏰ 트리거에서 '실행' 기록이 최근인지 볼 것 (없으면 `DG_installTrigger`).
**실제로 없었다** — 2026-11-09 에 확인해 보니 트리거가 아예 등록돼 있지 않았다. 그때까지
시트 손 수정은 GitHub 동기화로만 들어왔다 (이희옥 8강 '과제' 가 늦게 뜬 것도 이 길이다).
그날 등록하고 `DG_pushToDb` 를 손으로 한 번 돌려 '맞출 것이 없습니다 (시트 6375칸 확인)'
— 그 시점에는 시트와 DB 가 같았다.

⚠️ **그 10분 사이에 저장하면?** 화면은 시트의 새 O 를 빈칸으로 본다. 그대로 저장하면 X 가
나가 O 를 덮었다 — 관리자 출석 관리는 DB 로 읽은 뒤로 이 구멍이 계속 있었다. GAS v32 부터
사람마다 '본 값'(`seen`)을 받아 시트의 지금 칸과 다르면 쓰지 않고 `changed` 로 돌려준다
(`docs/RULES.md`). **v32 를 배포해야 켜진다** — v31 은 `seen` 을 모르니 무시하고 예전처럼 쓴다.

⚠️ **'오늘' 은 기기 날짜다** (`getToday()` = `todayISO()`). GAS 의 `today` 가 그 왕복에 딸려
왔는데 왕복을 없앴다. 미래 회차 저장은 GAS 가 서버 시계로 한 번 더 막는다. 검증은
`page.clock.setFixedTime` 으로 날짜를 고정해야 한다.

⚠️ **회차 목록도 DB(`dg_sessions`)다.** 시트에 새 회차 열을 붙이면 다음 동기화 뒤에 선택칸에
나온다. 학기 회차를 미리 다 만들어 두는 지금 방식에서는 문제가 안 된다.

### 6-10. GAS 읽기(`doGet`)에는 열쇠가 있다 — 동기화만 들고 간다 (GAS v33)

**2026-11-13 부터 잠겨 있다.** 열쇠 없이 `/exec` 를 열면 `읽기 열쇠가 맞지 않습니다` 가 나오고,
동기화는 로그에 `🔑 읽기 열쇠: 보냄` 을 찍고 정상으로 돈다 (그날 네 번 확인).

`doGet` 주소는 앱 코드(`members-data.js`)에 적혀 있어 누구나 안다. 열쇠 없이 부르면 명단 ·
전 회차 출결 · 김밥 · 과제 내용이 **통째로** 나왔다. 앱은 v131 부터 이 주소를 읽지 않으므로
(함정 6-9) 부르는 것은 GitHub 동기화 하나뿐이다.

```
GAS 스크립트 속성  DG_READ_KEY   (dev 계정 독립 프로젝트 → 프로젝트 설정)
GitHub Secret     GAS_READ_KEY  (저장소 → Settings → Secrets and variables → Actions)
        └─ 같은 값. 동기화가 ?key= 로 실어 보내고, GAS 는 시트를 열기 전에 견준다
```

- **속성이 없으면 예전처럼 열려 있다.** v33 을 먼저 올려도, Secret 을 먼저 넣어도 동기화가
  안 깨진다. **잠기는 것은 `DG_READ_KEY` 를 넣는 순간**이다 (재배포 필요 없음)
- 지금 잠겨 있는지는 dev 프로젝트 편집기에서 `DG_authorizeAndCheck` 를 실행하면 마지막 줄이 말한다
- 값이 어긋나면 동기화가 **`읽기 열쇠가 맞지 않습니다`** 로 멈추고 DB 는 건드리지 않는다.
  로그가 어느 쪽을 볼지 말해 준다. 열쇠 값 자체는 로그에 안 찍힌다 (Actions 로그는 공개다)
- **열쇠를 잃어버렸거나 바꿀 때**: 두 값은 어디서도 다시 볼 수 없다고 생각할 것 (GitHub 은
  Secret 을 안 보여 준다). 새 값을 정해 **Secret 을 먼저, 스크립트 속성을 나중에** 바꾼다 —
  그 사이 동기화 한 번이 실패할 뿐이다. 재배포는 필요 없다
- ⚠️ **`doPost` 에는 열쇠가 없다** — 앱이 쓰는 길(출석 저장 · 동기화 실행)이라 걸 수 없다.
  이름+뒤 4자리만 알면 지난 회차 O/X 를 쓸 수 있는 것은 그대로다 ('알려진 한계')
- 아주 오래 열어 둔 옛 앱(v130 이하)은 조장 화면에서 `doGet` 을 부른다. 잠근 뒤에는 출결을
  못 불러오고, 새로고침하면 새 버전이 된다

### 6-11. 관리자 로그인 — 무엇을 막고 무엇을 안 막는가 (v134 · GAS v34)

**화면의 로그인 확인은 아무것도 막지 못한다.** 브라우저 코드는 누구나 고쳐 쓸 수 있다.
v133 까지는 `script.js` 가 비밀번호를 글자로 견줬고(공개 저장소에 평문), `admin.js` 는
`sessionStorage.adminLoggedIn` 이 **있기만 하면** 들여보냈다. 게다가 로그인 없이도 관리자
화면이 하는 일이 전부 됐다. 그래서 **로그인과, 그 로그인이 실제로 막는 서버 쪽을 함께** 바꿨다.

| | 누가 확인하나 | 어디 |
|---|---|---|
| 비밀번호 | Supabase Auth (틀린 시도 제한도 거기서) | `scripts/admin-auth.js` — `fetch` 만 |
| 관리자인가 | 계정의 `app_metadata.dg_admin` — **사용자가 스스로 못 바꾸는 칸** | `supabase/dg_admin.sql` |
| 나이 · 담당교역자 읽기 | **DB** — 열 권한을 뺐고, 관리자 토큰을 확인하는 함수로만 준다 | `dg_admin_lock.sql` · `dg_admin_member_extras` |
| 동기화 실행 · 출석 기록 지우기(빈 값 저장) | **GAS** — 토큰을 Supabase 에 물어 확인 (5분 캐시) | `doGet.js` `DG_isAdmin_` |

- 화면에서는 아이디만 쳐도 된다. `@` 가 없으면 `@plch.or.kr` 를 붙인다(`ADMIN_EMAIL_DOMAIN`).
  **어떤 계정이 관리자인지 · 비밀번호는 Supabase 대시보드에만 있다**(Authentication → Users) —
  코드 · 문서에 적지 않는다. `dg_admin.sql` 의 `v_email` 도 고쳐서 실행만 하고 커밋하지 않는다
- ⚠️ `dg_admin.sql` 3번은 메일이 틀리면 **오류로 멈춘다.** 처음에는 `update` 가 조용히 0줄을 고치고
  성공으로 끝나, 표시가 안 붙은 줄 모르고 넘어갈 뻔했다
- 관리자를 더 두려면: 대시보드에서 계정을 만들고 `dg_admin.sql` 3번을 그 메일로 한 번 더
- 세션은 `sessionStorage`(탭을 닫으면 로그아웃). 토큰은 1시간짜리라 만료 1분 전에 새로 받는다
- **비밀번호를 잊었으면** 대시보드 Authentication → Users 에서 다시 정한다

⚠️ **`dg_members` 를 `select=*` 로 읽지 않는다.** anon 에게 `age` · `pastor` 열이 안 열려 있어
`*` 는 통째로 거절된다(42501) — 조회 화면이 죽는다. `members-data.js` `MEMBER_PUBLIC_COLUMNS`.
⚠️ **표에 열을 더하면** anon 은 그 열을 못 읽는다. 화면에서 쓸 열이면 `dg_admin_lock.sql` 을
한 번 더 실행하고(나이 · 교역자만 빼고 전부 다시 열린다) `MEMBER_PUBLIC_COLUMNS` 에도 적는다.
⚠️ 나이 · 교역자는 `localStorage` 캐시에 **안 쓴다** (`withoutAdminFields`). 쓰면 그 브라우저의
다음 사람이 로그인 없이 읽는다. 못 받아 왔을 때는 관리자 화면 동기화 줄이 빨갛게 말한다.
⚠️ 검증은 `asAdmin(page)` 로 들어간다 (`tests/lib/harness.mjs`) — **`**/rest/v1/**` 가짜를 건
뒤에, 같은 page 에.** 순서가 바뀌면 나이 · 교역자가 조용히 빈다.

**이것으로도 안 막히는 것** (조장에게는 계정이 없다 — 조회 · 조장 확인을 서버로 옮겨야 닫힌다):
누구나 O/X 를 쓸 수 있다 · 현 기수 명단(이름 · 뒤 4자리 · 조)과 출결 · 김밥 · 과제 내용이 공개다.

### 7. 시트에서 지운 것이 DB 에서 안 지워질 수 있다

`upsert` 만 하는 표는 **한 방향 톱니바퀴**다. 시트에서 값을 지워도 DB 에 남는다.

| 표 | 정리 |
|---|---|
| `dg_lunch` | ○ (`sync-sheet-to-db.mjs` 김밥 절) |
| `dg_attendance` | ○ (이번에 넣었다. 안전장치 있음 — 많이 지우려 하면 멈춘다) |
| `dg_homework` | **거의 ✕** — **내용이 빈 행만** 지운다. 시트에서 지운 진짜 제출은 남는다 |
| `dg_sessions` | **✕** — 지운 회차가 유령으로 남는다. 아직 안 고쳤다 |
| `dg_members` | 지우지 않고 `inactive` 로 내린다 (**의도한 것** — 이력 보존) |

⚠️ `dg_members` 는 `(cohort_id, name, phone)` 로 upsert 한다. 같은 기수에 같은
이름+뒤 4자리로 다시 들어오면 **같은 uuid 를 물려받아 옛 출결이 딸려 온다.**

  브라우저에 전원이 내려간다.** 출결 · 김밥 · 과제 내용(제출 링크)도 읽힌다 — 과제 내용은 조원이
  자기 제출물을 여는 데 써서, 본인 확인을 서버가 하기 전에는 가릴 수 없다.
- **GAS `doPost` 로 누구나 O/X 를 쓸 수 있다.** 이름+뒤 4자리만 알면 지난 회차를 O/X 로 바꿀 수
  있다(한 번에 100명). 조장에게는 계정이 없어서다. 되돌리는 길은 시트 버전 기록이다.
  지우기(빈 값)와 동기화 실행은 v34 에서 관리자만, 읽기(`doGet`)는 v33 에서 열쇠로 막았다.
- 위 둘을 닫으려면 **조회와 조장 확인을 서버로 옮겨야 한다** (이름+뒤 4자리를 서버 함수가 확인하고
  본인 · 자기 조 것만 준다 · 시도 횟수 제한). 큰 작업이라 따로 결정한다.
- 공개 저장소에 있던 **옛 기수 명단 파일은 지웠다** (2026-11-13) — `data.json`(286명) · CSV 7개 ·
  옛 사본 폴더 `DG 조배치 검색기/` · 그것을 만들던 파이썬 도구. 저장소가 Pages 로 그대로 나가서
  주소만 알면 내려받아지는 상태였다. ⚠️ **git 이력에는 남아 있다** — 지난 커밋을 열면 보인다.
  이력까지 지우려면 이력 다시 쓰기 + 강제 푸시가 필요하다 (결정 대기).
  `.md` 자동 복사(Drive · `dev-plc/knowledge-base`)는 새로 쓰기만 하고 지우지 않으므로 옛 문서
  사본이 거기 남는다.
