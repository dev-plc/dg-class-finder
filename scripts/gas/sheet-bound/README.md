# 시트에 붙은 GAS (출석부(DB) 스프레드시트)

**GAS 프로젝트가 둘이다.** 헷갈리면 엉뚱한 쪽을 고치고 아무 일도 안 일어난다.

| | 이 폴더 | `scripts/gas/doGet.js` |
|---|---|---|
| 어디에 있나 | **출석부(DB) 시트에 직접 붙어 있다** (확장 프로그램 → Apps Script) | dev 계정의 **독립 프로젝트**. `SHEET_ID` 로 시트를 연다 |
| 무엇을 하나 | 시트 안에서 도는 일 — 메뉴 · `onEdit` · `onFormSubmit` | 웹앱(`doGet`/`doPost`). 앱과 GitHub Actions 가 부른다 |
| 배포 | **필요 없다.** 붙여넣고 시트를 새로 열면 끝 | 배포 → 배포 관리 → ✏️ → **새 버전** (새 배포 금지 — URL 이 바뀐다) |
| 버전 | 없음 | `DG_VERSION` |

## 파일

### `과제제출.gs` — 출석부(DB)에 `'과제'` 를 쓴다

`과제제출` 탭(폼 응답)에 `'과제+소감문'` 이 들어오면, 출석부(DB)의 그 사람 ·
그 강의 칸이 `X`·`x` 일 때 **`'과제'` 로 바꾼다.**

- `onEdit` — 손으로 고칠 때
- `onFormSubmit` — 폼 응답이 들어올 때
- `syncAllAttendance()` — 메뉴 '전체 결석 일괄 동기화'. 과제제출 탭 전체를 다시 훑는다

**앱이 이 값을 어떻게 세는지는 `docs/RULES.md` 가 단일 출처다.** 요약하면
`'과제'` 는 **출석으로 인정**되고, 그래도 **결석자 명단에는 뜬다**(심방 대상).

⚠️ **인정 기준을 이 파일과 앱이 나눠 갖고 있다.** 위 `indexOf('과제+소감문')` 과
`members-data.js` 의 `isFullHomework()` 는 **같은 규칙이어야 한다.** 한쪽만 고치면
시트는 칸을 안 바꿨는데 화면은 인정하는(또는 그 반대의) 어긋남이 난다.

⚠️ **`'◎'` 는 덮지 않는다.** 원본에는 `'◎'`(지난 기수 이수)도 덮는 조건이 있었다.
`◎` 는 결석이 아니고, 덮으면 되돌릴 길이 시트 버전 기록뿐이다. 이 사본에서 뺐다.

원본과의 **실제 코드 차이는 그 두 줄뿐**이다 (나머지는 주석). 확인해 보니
**이 기수 시트에는 `◎` 가 하나도 없어서** 붙여넣어도 지금 달라지는 것이 없다 —
지난 기수 이수자가 재참여해 누가 `◎` 를 적는 날을 위한 보호다. 급하지 않다.

⚠️ `normalizeString()`(공백 제거 + 소문자)은 `doGet.js` 의 `DG_normalizeId_()` 와
**규칙이 다르다.** 전각 숫자(`５３２６`)를 안 고친다. 그래서 같은 사람인데 한쪽만
찾는 일이 생긴다 — 어긋난 아이디는 **DGfinder → 과제 아이디 점검**(v29) 이 찾아 준다.

### `정리.gs`

- `runOrganizeFromLib()` — `SheetLib` 라이브러리로 행 정렬 (`YF·YM·C·남·여·O·V` 순)
- `markDolbom()` — `돌봄일정` 탭을 보고 **빈칸에만** `'돌봄'` 을 쓴다.
  이미 값이 있는 칸은 안 건드린다

### `onOpen.gs`

시트 메뉴 `🛠️ 출석부 관리`. `doGet.js` 의 `DG_addMenu(ui)` 를 여기서 같이 부르면
'과제 아이디 점검' 메뉴도 뜬다.

## ⚠️ `code.gs` (v18) 는 지울 것을 권한다

시트 프로젝트 안에 **`doGet`/`doPost` 가 든 v18 DGfinder 사본**이 남아 있다.
배포되는 것은 dev 계정의 별도 프로젝트(v28+)이므로 이것은 죽은 코드인데,
그냥 두기에는 위험하다.

- `headers.forEach` 로 **헤더 열을 통째로 내보낸다** — 연락처·결혼 여부까지.
  이 저장소의 `doGet.js` 는 v19 에서 그것을 없애고 화면이 쓰는 열만 담는다
- 그 프로젝트를 실수로 웹앱 배포하면 그대로 샌다

그래서 저장소에도 사본을 두지 않는다.

**지워도 나머지 세 파일은 그대로 돈다.** `code.gs` 가 만드는 이름
(`SHEET_ID` · `TAB_ROSTER` · `TAB_LINKS` · `TAB_LUNCH` · `doGet` · `doPost`)을
참조하는 곳이 이 폴더에 하나도 없다 — 메뉴 · `onEdit` · `onFormSubmit` ·
`syncAllAttendance` · `runOrganizeFromLib` · `markDolbom` 전부 자기 파일 안에서 끝난다.

지우기 전 **`배포 → 배포 관리` 가 비어 있는지**만 확인할 것. 항목이 있으면 그 URL 을
누가 쓰는지 알 수 없다.
